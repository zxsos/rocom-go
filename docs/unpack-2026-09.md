# 解包方法(2026-09 版,给 AI/新机器照做)

> 适用:2026-09-10 起(安卓 **1.111.0.112** 及同期 PC)。老版本 pak 不受影响,旧方法仍可用。
> 本文是操作手册;原理沉淀到 `docs/data.md` 前先在此登记。

## 0. 一句话结论

**加密换了**。新 pak 必须用带「可配置加密」的 **LukeFZ/CUE4Parse fork**(commit `2b09c12`),
上游 `FabianFG/CUE4Parse` 解新 pak 的表现是「10 个包全部挂载成功、但 0 个文件」。
AES 主密钥 **没换**,还是 `0x34254D23E47299B3B7F6C4CFDE9BD0688703446D9D8F37B2EBDDDE5B06ED5ADF`。

> ⚠️ **2026-10 的 PC pak(WeGame 版)要再新一档:用 `ec1f129a`,`2b09c12` 解不出 `all.pb`。**
>
> 症状**极具欺骗性**:挂载正常、绝大多数文件正常,只有
> `NRC/Content/ScriptC/Data/PB/all.pb` 与 `proto.non` 报
> `Failed to decompress Zlib data (Expected: 65536, Result: 0)` —— 补丁包(`_N_P`)里的
> 那两份走 chunked crypto,而 `2b09c12` 的 pak reader 会把整个 buffer 都当成有用数据解密
> (修于 `0b1f0b33` *fix pak file reader always crypting the whole buffer instead of the used
> portion*),且未区分「未压缩文件才走 chunked」(修于 `ec1f129a`)。
>
> 不报错、不中断,只是那 2 个文件静默缺失 —— 而 `gen_gamedata` 的 opcodes/枚举全靠
> `all.pb`,拿不到就只能退回基础包里的旧版:**实测 opcodes 1382 → 1245,少 137 个**。
> 两条自查:① `ls -l parsed/NRC/Content/ScriptC/Data/PB/all.pb` 应约 **1.1MB**
> (基础包旧版只有 0.9MB);② 解包失败条目数 **82 → 54**。

## 1. 变了什么

2026-09 起 pak 加密从「固定 permute+mutate 变体」升级为 `FConfigurableCrypto`:

- pak trailer **末尾多 1 字节 `strategy id`**(`SizeRocoKingdomWorld = Size8a + 1`)
- strategy 决定 *(算法, 密钥来源)*:
  - 算法表:`AES / SM4 / MLE / RC5 / XTEA / Speck / Salsa20 / Simon / ChaCha20`(目前实际只见到 AES 与 MLE)
  - 密钥来源:主密钥 / `_keyMaterial[1..4]` 派生 / **按 pak 文件名派生**
  - 编排:`strategy=0` 是 (主密钥, AES);此后每个算法占 5 个号位 →
    `idx = strategy - 1; 算法 = idx // 5; 槽位 = idx % 5`,槽位 4 是「文件名派生」,0..3 是 `_keyMaterial[1..4]`
- 密钥派生:SHA1/MD5 + 固定种子 `NRC_CRYPTO_OBFUSCATION_SEED2026\x07`
- 文件条目可能再套一层 `FConfigurableCryptoInfoHeader`(magic `0x7C3F9A215E8B4D26`),并按 0x1000 分块解密
- pak 版本号也从 11 升到 **12**(`unsupported version 12` 只是警告,不致命)

参考实现:LukeFZ 的 `FConfigurableCrypto.cs` / `FConfigurableCryptoAlgorithm{AES,MLE}.cs` /
`NRCPakFileReader.cs`(commit [2b09c12](https://github.com/LukeFZ/CUE4Parse/commit/2b09c12f558feb8c2e6db42fa4570d4c78481848);
2026-10 的 PC pak 还需 [ec1f129a](https://github.com/LukeFZ/CUE4Parse/commit/ec1f129a65e21eea54d2772c6b393dc237119494)
的 pak reader 修复)。

## 2. 环境(Linux 全新机器)

```bash
# 1) .NET SDK 10+(C# 解包器需要;Debian 还要先装 libicu,否则 dotnet 启动即崩)
sudo apt-get install -y libicu76 build-essential        # Debian 13
curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 10.0 --install-dir "$HOME/.dotnet"
ln -sf "$HOME/.dotnet/dotnet" /usr/local/bin/dotnet && dotnet --version   # 应 ≥ 10.0

# 2) LukeFZ fork(上游不支持新加密),按 SHA 取,别用默认分支(默认分支是 2025-11 的旧版)
#    2026-10 的 PC pak 必须用 ec1f129a(nrc2 分支),2b09c12 解不出 all.pb —— 见开头告警
git clone https://github.com/LukeFZ/CUE4Parse.git ~/Git/gh/CUE4Parse-LukeFZ
cd ~/Git/gh/CUE4Parse-LukeFZ
git fetch --depth 1 origin ec1f129a65e21eea54d2772c6b393dc237119494
git checkout FETCH_HEAD

# 3) uv(后置步骤 .bytes→JSON 需要)
#    https://docs.astral.sh/uv
```

## 3. 解包

```bash
cd <repo>

# PC:指向游戏安装目录的 Paks
CUE4PARSE_DIR=~/Git/gh/CUE4Parse-LukeFZ ./scripts/unpack.sh --paks "<安装目录>/Win64/NRC/Content/Paks"

# 安卓:直接喂 .apk(解包器会自己找 apk 内嵌的 main.obb.png)
CUE4PARSE_DIR=~/Git/gh/CUE4Parse-LukeFZ ./scripts/unpack.sh --paks ~/Downloads/rocom/android/nrc-1.111.0.112.apk

# 先看看能挂出多少文件,再决定要不要全量导
CUE4PARSE_DIR=~/Git/gh/CUE4Parse-LukeFZ ./scripts/unpack.sh --paks <路径> --list | tail -5
```

`unpack.sh` 会自动:应用 NRCLua luac 补丁 → 构建 → 导出到 `~/Downloads/rocom/parsed`
→ `.bytes` → 紧邻 `.json`(`bin2json.py`)→ `.luac` → `.lua`(`decompile_luac.sh`,需 unluac)。
若 CUE4Parse 缺 `FConfigurableCrypto`,脚本会打印警告并给出换 fork 的提示。

**验证过的输出**(安卓 1.111.0.112,2026-09-10):

```
挂载 10 个包,35069 个文件(689ms)        ← 关键:不是 0 就说明密钥/算法对了
OODLE ERROR : OodleLZ_Decompress: ...   ← 130 个 BigMap 条目失败,见第 6 节
完成(2.5s): package 349, raw 22860,png 55;跳过 0,失败 130
解码 1096,跳过 0,失败 5(共 1101 个 RocoBinData)
未找到 unluac(AUR: unluac),跳过 luac 反编译
```

## 4. 先诊断再解包(推荐)

`scripts/pakinfo.py` 零依赖(内置 AES-256),直接告诉你「密钥还行不行 / 用的是哪个 strategy」:

```bash
uv run python scripts/pakinfo.py "<Paks 目录>"     # 或 单个 .pak / 安卓 .apk
uv run python scripts/pakinfo.py <路径> --aes 0x<新密钥>
```

输出判读:

| 输出 | 含义 |
| --- | --- |
| `strategy=5(AES+文件名派生)解密成功 → mount='../../../'` | 密钥有效,可以解 |
| `strategy=11(MLE+keyMaterial[1]) … 本脚本未实现` | 需 LukeFZ fork 的 CUE4Parse(MLE 算法) |
| 两行 `✗` + `结论: 密钥失效` | 密钥或格式又变了,先别跑全量解包 |
| `索引未加密 → mount='/'(占位包,不计入判定)` | 340 字节空壳包(安卓 obb 里的基础包如此) |

## 5. 安卓包怎么拿、有什么坑

- 官网 <https://rocom.qq.com/> 的下载二维码指向 `https://rocom.qq.com/zlkdatasys/mct/d/play.shtml`,
  该页的 `MCTCFG` 会被 `https://img.itop.qq.com/js/1110613799.js` 覆盖 —— **最新的 `androidURL` 在那个 js 里**,
  页面里的默认值可能是上一版的。格式:
  `https://dlied4.myapp.com/myapp/1110613799/cos.release-75793/<id>_com.tencent.nrc_<a>_<版本>_<rand>.apk`
  (1.111.0.112 是 2026-09-08 的 1.30GB 包;官网渠道 / 微信 / 手Q / 默认 四个 id)
- 游戏资源在 APK 的 **`assets/main.obb.png`**(伪装成 png 的 zip,1.03GB),解包器可直接吃 .apk。
- ⚠️ **坑**:obb 里 5 个基础 pak 是 **340 字节空壳**,有内容的只有 `*_3_P.pak` 补丁包 ——
  美术资源(宠物图、UI 图标、大地图瓦片)在基础包里,**安卓这条路拿不到**;
  Bin 配置(`PETBASE_CONF` / `SKILL_CONF` / `dev_CN` 本地化)、`ProtoCMD.luac`、lua 脚本则齐全。
  要更新图片类生成物,必须走 PC 完整客户端。
- PC 端官网只提供 12.8MB / 29MB 的**下载器**(里面没有 CDN 直链),完整包要经 WeGame 客户端,
  所以远程机器拿不到 PC pak —— 在有客户端的机器上跑。

## 6. 已知残留问题

- **130 个 `NRC/Content/ScriptC/Data/BigMap/*.bytes` 解压失败**(安卓包实测):
  `Failed to decompress Oodle data (Expected: 65536, Result: 0)` / `OODLE ERROR: invalid header`。
  oodle 库本身是下载成功的(`~/.cache/nrc-unpack/liboodle-data-shared.so`),所以是**解密后仍不是合法 Oodle 流**
  —— 这些条目用的 strategy 在 LukeFZ 实现里多半还不完整(`NRCPakFileReader.NRCExtractEntry` 先
  `DecryptChunked` 再解压)。要修就得跟 LukeFZ 的实现 / 上游 issue。
- `unluac` 未装 → 6178 个 `.luac` 未反编译(含 `ProtoCMD.luac`,影响 `gen_pbdesc` 的 opcode→消息名)。
- 安卓补丁包里 **没有 all.pb**(`gen_proto` 的输入),proto 更新仍要靠 PC 客户端。
- `bin2json` 有 5 个失败:`BinDataCompressed_ROW/*.bytes` 缺同名 schema `.non`(基础包缺失所致)。
- `pakchunk*_3_P.pak` 报 `unsupported version 12` 是警告,不影响解包。
